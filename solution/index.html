Solution Overview

让最高权限按需而来、到期即走

TEAM（Temporary Elevated Access Management）基于 IAM Identity Center，为多账号环境提供「申请 → 审批 → 自动授权 → 到期回收 → 审计」的临时提权闭环。会话中的每一次 API 调用通过 EventBridge 近实时推送写入 DynamoDB，审计员在 TEAM 界面里秒级可见。

01为什么需要临时提权

⚠️

常驻权限风险高

长期挂着 Admin 的账号一旦被盗用，攻击窗口就是无限的。

🧾

合规需要可追溯

谁、在何时、因为什么工单、拿了哪个账号的什么权限，都要留痕。

⏱️

运维又不能被卡住

紧急变更需要快速拿到权限，流程不能比人工找管理员还慢。

⚙️

💰

05权限集设计建议

TEAM 授权的单位是 IAM Identity Center 权限集，任何权限集都可以临时授予，不只限于 Admin。建议按运维任务拆分最小权限，统一使用 TEAM- 前缀。

权限集典型内容场景建议时长审批
TEAM-ReadOnlyReadOnlyAccess排查问题、查看配置8 小时可免审批
TEAM-EC2-OpsEC2 启停、改实例类型日常运维变更4 小时需审批
TEAM-DB-OpsRDS 快照、参数组、重启数据库变更窗口4 小时需审批
TEAM-BillingBilling财务临时查账8 小时需审批
TEAM-BreakGlassAdministratorAccess紧急事故1 小时严格审批

🎛️ 每个权限集可单独配置

谁能申请（组 / 用户 × 账号 / OU）、最长时长、是否需要审批、由谁审批。

⚠️ 两点注意

① 不要用已分配到 Management 账号的权限集，委派管理员管不了；② 会话时长建议设 1 小时，缩短授权结束后会话仍有效的窗口。

Architecture

三层账号 · 一条实时审计流

TEAM 部署在专用委派管理员账号；用户与组统一由 IAM Identity Center 管理；目标账号只承受临时分配。审计事件从每个成员账号的 default bus 推送到中心总线，写入 DynamoDB 供 TEAM 读取。

03关键设计

🔑 主键设计

pk = 账号ID#用户名，sk = eventTime#eventID。与原 Lake SQL 的过滤条件（账号、用户、时间窗）一一对应，查询为单次 Query，不再扫描。

📖 只读事件也要

EventBridge 规则默认只匹配写操作；转发规则与中心规则都设为 ENABLED_WITH_ALL_CLOUDTRAIL_MANAGEMENT_EVENTS，才能记录 Describe / List。

🌐 全局服务

IAM、STS 等全局服务事件出现在 us-east-1，所以转发规则默认部署 us-west-2 + us-east-1，可通过 FORWARDER_REGIONS 扩展。

🧩 前端零改动

返回字段保持 eventID / eventName / eventSource / eventTime，GraphQL 与 React 页面原样复用。

Deployment Guide

五条命令，把坑都提前填好

以下流程来自一次从零开始的真实部署，常见问题都已固化进脚本：参数默认值、部署前预检、自动创建组织 Trail、等待中心总线就绪后再下发。

01前置条件

🏛️

组织与身份

Organizations 全部功能；Identity Center 组织实例；记下门户 URL 和 Region。

👥

组与权限集

team_admin、team_auditor、申请组、审批组；TEAM 用的权限集不要分配到管理账号，会话时长建议 1 小时。

🔐

代码仓库与密钥

Fork 到私有 GitHub；TEAM 账号中建 Secrets Manager 密钥，键 url + AccessToken。

02部署步骤

填写参数 2 分钟

模板已默认 eventbridge 模式和 CACHE_TTL，每一项都有注释。

cd iam-identity-center-team/deployment
cp parameters-template.sh parameters.sh   # 按注释填写
aws sso login --sso-session <session>

委派管理员 1 分钟

把 TEAM 账号设为 Account / CloudTrail / Identity Center 的委派管理员。

./init.sh

部署 TEAM ~20 分钟

先自动跑预检，再创建主栈并触发 Amplify 构建。

./deploy.sh   # 内含 ./preflight.sh

部署审计转发 ~5 分钟

无组织 Trail 时自动创建；等待中心总线就绪后用 StackSets 下发到所有成员账号。

./deploy-forwarder.sh

SAML 集成 5 分钟

在 Identity Center 添加自定义 SAML 2.0 应用，属性映射 Subject=${user:subject}(persistent)、Email=${user:email}(basic)，并分配四个组。

./integration.sh   # 输出 Start URL / ACS URL / Audience
cp details-template.json details.json   # 填入 SAML metadata URL
./cognito.sh

配置策略并验证 完成

管理员建 Eligibility / Approver 策略（Ticket No 必填）→ 申请 → 审批 → 在转发 Region 内操作 → 查表。

aws dynamodb scan --table-name team-session-events-main \
  --query "Items[].[eventTime.S, ingestTime.S, eventName.S, pk.S]" --output table

03踩过的坑与已内置的修复

#问题已做的处理级别
01CloudTrail Lake 不接受新客户
审计模式设为 read/write/none 时会尝试创建 Event Data Store，报 InvalidRequest 后整个构建回滚。		默认 CLOUDTRAIL_AUDIT_LOGS=eventbridge，预检对 read/write/none 发出警告阻断
02none 仍会创建 Lake
模板条件把 none 也算作「创建」，只是关闭摄入。		改用 eventbridge 模式；文档注明 none 的真实含义阻断
03缺少 CACHE_TTL
CloudFormation 报 Parameter 'cacheTTL' must be a number。		模板写入默认值，deploy.sh 兜底 604800，预检校验易错
04密钥建错账号 / 键名不对
密钥必须在 TEAM 账号同 Region，键名精确为 url / AccessToken。		预检读取密钥并校验键名易错
05GitHub 私有仓库 Repository not found
gh 登录不等于 git 凭证；Fine-grained token 不被支持。		文档要求 classic token（repo + admin:repo_hook）并执行 gh auth setup-git易错
06SSO token 过期
长时间操作后所有 CLI 命令失败。		预检逐个校验 profile 并提示 aws sso login易错
07Management 账号缺少分配
aws configure sso 列表里看不到管理账号。		文档列出：给运维用户在管理账号单独分配权限集易错
08自定义资源缺 cfnresponse
经 Amplify 打包的 Lambda 没有该模块，栈卡 1 小时后回滚。		改为 urllib 直接回传，出错也立即返回 FAILED阻断
09没有组织 Trail
CloudTrail → EventBridge 需要正在记录的 Trail，否则一条事件都没有。		deploy-forwarder.sh 检测并自动创建组织 Trail阻断
10总线未就绪就下发转发
Amplify 构建约 20 分钟，提前下发会转发失败。		脚本轮询总线策略包含组织 ID 后再部署 StackSet易错
11在错误 Region 测试
控制台默认 Region 不在转发范围，表里一直为空。		FORWARDER_REGIONS 可配置；验证清单强调 Region易错
12聊天复制带入反斜杠
IDC\_LOGIN\_URL 这类变量名导致参数缺失。		预检检测 \_易错

04交付给客户前的检查清单

✅ 功能

申请 / 审批 / 自动授权 / 到期回收 / 提前撤销；审计员可见全部记录；Session activity 有数据。

🔒 安全

TEAM 账号不放其他负载；权限集按任务收窄；用户启用 MFA；保留 break-glass 访问。

💰 成本

DynamoDB 按需 + TTL；组织 Trail 首份管理事件免费，仅 S3 存储；无 CloudTrail Lake 摄入费。

🧹 回退与清理

改回 ARN / read 模式即可回退；删除 StackSet、Amplify 应用、主栈与 SAML 应用即可清理。
